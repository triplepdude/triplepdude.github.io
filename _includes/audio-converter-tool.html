{%- comment -%} The audio converter: drop zone, file list, waveform editor, output options and script. It is the whole body of /mp4-to-mp3/ and of each page for one conversion (M4A to MP3, WAV to MP3 and so on). A page includes it once, after its front matter: {% raw %}{% include audio-converter-tool.html format="mp3" source="audio" trim="folded" hint="M4A, M4B or AAC files, as many as you like. Nothing is uploaded." %}{% endraw %} The sound is read, decoded and written by assets/js/audio-engine.js (window.TTAudio; its header comment documents what it does and throws); this file is the page around it. Every parameter is optional. With none, the page is exactly MP4 to MP3. Text values are plain text (no HTML or Markdown). Put each value in double quotes, or in single quotes when the text contains a double quote. format Output format selected when the page opens: mp3, wav or copy (the AAC sound copied unchanged into .m4a, "Original audio"). Default mp3; a value that is unknown or not in formats gives the first of formats. Options that do not apply to it start hidden, so nothing moves when the script runs. formats The formats offered and their order, separated by spaces, such as "wav mp3". Default "mp3 wav copy". Unknown words are ignored; none left gives the default. Messages that suggest another format name only formats on offer. Without SIMD (no MP3 encoder) the first other format is chosen instead of MP3. With one format the Format choice is not shown, and without SIMD a page that offers only MP3 converts nothing and says why. hint The small line in the drop zone. Default "MP4, MOV, WebM, MKV, M4A, MP3, WAV, OGG or FLAC. Only the audio is read, so long phone videos of several GB work. Links and protected (DRM) files cannot be converted." Every input format is still accepted, whatever the hint names. drop_title The drop zone's first line. Default "Drop videos or audio files here". source video or audio: what the page expects the visitor's files to be, for the few sentences that name them. Default video. With audio, a dropped link is answered "Save the file to your device first" (not "the video"), and a file that cannot be read is "not an audio file" (not "a video or audio file"). trim open or folded. open (the default) shows the waveform editor (waveform, start and end, play, fades and volume) as soon as a file is added; folded puts it inside a closed "Trim, fades and volume" section the visitor can open, and the editor's heading reads "Edit" instead of "Trim". Either way the sound is scanned for its peak, so the volume readout is ready. kbps Starting MP3 bitrate: 64, 96, 128, 160, 192, 224, 256 or 320. Default 192; another value also gives 192. channels Starting channel choice: keep (as in the file) or mono. Default keep. presets MP3 preset buttons, separated by spaces, shown in their own "Presets" row above the bitrate: music ("Music: 192 kbps", channels as in the file), speech96 ("Speech: 96 kbps mono") and speech64 ("Speech: 64 kbps mono"). Each sets the bitrate and channel fields. Default: no row, and the hub's one button "Speech: 96 kbps mono" beside the channels. tags basic or all. basic (the default) writes the title, artist and album of the Tags fields and the cover. all also keeps the file's other tags (album artist, composer, date, genre, track and disc numbers, comment, lyrics), listed in a "Keep the file's other tags" checkbox, ticked to start with, under the fields. saving show: a converted file's line compares the sizes ("105.8 MB WAV → 14.4 MB MP3, 86% smaller"; of the part selected, when trimmed), a line above the results adds up two or more, the size estimate says how much smaller the result will be, and the MP3 hint compares a minute with 16-bit WAV at 44.1 kHz. Default: sizes only. stream big: an MP3 estimated at 200 MB or more is written straight to a file the visitor chooses, as it converts, where the browser has showSaveFilePicker (Chrome and Edge 86 on a computer, Chrome 132 on Android): Convert asks where to save the first such file, one a press, and converts it with the files that need no asking. Where it has not, an MP3 is built in memory up to TTAudio.limits.wav (2 GB, 300 MB on a phone), and a bigger one is not converted: its file says why. Default: every MP3 is built in memory, with no limit. wav details: for WAV files the line under the name gives the bit depth ("PCM 24-bit", "32-bit float"), RF64 and BWF (a bext chunk); a note says when the header stated the wrong length and the sound was read to its real end, and a header that cannot be used is named in plain words (no format chunk, no channels or rate, a bit depth such as 12); a WAV that holds MP3 is saved as the MP3 inside, unchanged (cut without re-encoding when trimmed), unless the visitor unticks "Save the MP3 inside as it is" in the editor; the size estimate says when the rate changes; the MP3 hint says MP3 has no bit depth; the file picker also offers .bwf and .rf64 files. Default: WAV files are shown and converted like any other. Adding parameters (pair pages). Follow the pattern above: read the value into an acv_ variable below (strip, downcase, a default for unknown values), render the starting state into the HTML so nothing moves when the script runs, put it into CONF in the script, and document it here. The places are marked "Pair-page options": WAV bit depth and sample rate (add sampleFormat and sampleRate to convertOptions(), which the size estimate and TTAudio.convert both read; the engine writes 16 and 24-bit, float, µ-law and A-law and resamples), presets (the presets parameter, or beside the Speech button, which is the hub's one preset), and a switch that writes no tags (pass tags: null to TTAudio.convert in convertOne()). The script of presets, tags, saving, stream and wav is in its section "WAV to MP3 options". The element ids (m2m-...) are fixed, so a page holds one converter.
