{%- comment -%} The audio converter: drop zone, file list, waveform editor, output options and script. It is the whole body of /mp4-to-mp3/ and of each page for one conversion (M4A to MP3, WAV to MP3 and so on). A page includes it once, after its front matter: {% raw %}{% include audio-converter-tool.html format="mp3" source="audio" trim="folded" hint="M4A, M4B or AAC files, as many as you like. Nothing is uploaded." %}{% endraw %} The sound is read, decoded and written by assets/js/audio-engine.js (window.TTAudio; its header comment documents what it does and throws); the waveform's times, drawing, pointer rules and handle keys are shared with MP3 Cutter through assets/js/audio-wave.js (window.TTWave); this file is the page around them. Every parameter is optional. With none, the page is exactly MP4 to MP3. Text values are plain text (no HTML or Markdown). Put each value in double quotes, or in single quotes when the text contains a double quote. format Output format selected when the page opens: mp3, wav or copy (the AAC sound copied unchanged into .m4a, "Original audio"). Default mp3; a value that is unknown or not in formats gives the first of formats. Options that do not apply to it start hidden, so nothing moves when the script runs. formats The formats offered and their order, separated by spaces, such as "wav mp3". Default "mp3 wav copy". Unknown words are ignored; none left gives the default. Messages that suggest another format name only formats on offer. Without SIMD (no MP3 encoder) the first other format is chosen instead of MP3. With one format the Format choice is not shown, and without SIMD a page that offers only MP3 converts nothing and says why. hint The small line in the drop zone. Default "MP4, MOV, WebM, MKV, M4A, MP3, WAV, OGG or FLAC. Only the audio is read, so long phone videos of several GB work. Links and protected (DRM) files cannot be converted." Every input format is still accepted, whatever the hint names. drop_title The drop zone's first line. Default "Drop videos or audio files here". source video or audio: what the page expects the visitor's files to be, for the few sentences that name them. Default video. With audio, a dropped link is answered "Save the file to your device first" (not "the video"), and a file that cannot be read is "not an audio file" (not "a video or audio file"). trim open or folded. open (the default) shows the waveform editor (waveform, start and end, play, fades and volume) as soon as a file is added; folded puts it inside a closed "Trim, fades and volume" section the visitor can open, and the editor's heading reads "Edit" instead of "Trim". Either way the sound is scanned for its peak, so the volume readout is ready. kbps Starting MP3 bitrate: 64, 96, 128, 160, 192, 224, 256 or 320, or auto. Default 192; another value also gives 192. auto adds "Automatic" at the top of the bitrate list, chosen: each file then gets the bitrate that suits its source (autoKbps() in the script: lossless sound 320 kbps; lossy stereo 192, 256 from 200 kbps and 320 from 288 kbps; mono 96, or 128 above 112 kbps), shown on its card and in its size estimate, and the estimate says when a chosen bitrate is well above or below the source's. channels Starting channel choice: keep (as in the file) or mono. Default keep. alac decode: Apple Lossless (ALAC) files are decoded by the engine's own decoder (TTAudio.open(file, { alac: true })): 16 and 24-bit mono or stereo, a 24-bit file written as 24-bit WAV, and the bit depth shown on its line. Default: an ALAC file is refused as an unknown codec, as before. presets Preset buttons, separated by spaces, shown in their own "Presets" row above the options. For MP3: music ("Music: 192 kbps", channels as in the file), speech96 ("Speech: 96 kbps mono") and speech64 ("Speech: 64 kbps mono"), which set the bitrate and channel fields. For WAV, with wav_out="options" only: cd ("CD: 44.1 kHz 16-bit stereo"), video ("Video: 48 kHz 24-bit", channels as in the file), phone16 ("Phone: 8 kHz 16-bit mono") and phone-ulaw ("Phone: 8 kHz µ-law mono"), which set the bit depth, sample rate and channel fields. A button shows while its format is chosen, and the row while any of its buttons does. Default: no row, and the hub's one button "Speech: 96 kbps mono" beside the channels. tags basic, all or edit. basic (the default) writes the title, artist and album of the Tags fields and the cover. all also keeps the file's other tags (album artist, composer, date, genre, track and disc numbers, comment, lyrics), listed in a "Keep the file's other tags" checkbox, ticked to start with, under the fields. edit shows those tags as fields of their own instead: album artist, composer, genre, year (or date), track and disc number (each checked as typed), and keeps the file's comment and lyrics (named under the fields, not shown); it writes all of them (an MP3 gets ID3v2.3 and ID3v1 tags), names the cover's size, and adds a "Shrink cover art to 600 × 600 pixels" switch to the output options (off at first): a cover wider or higher than that is scaled down to fit (TTImage, assets/js/image-decode.js, loaded then), a PNG as PNG and anything else as JPEG. saving show: a converted file's line compares the sizes ("105.8 MB WAV → 14.4 MB MP3, 86% smaller"; of the part selected, when trimmed), a line above the results adds up two or more, the size estimate says how much smaller the result will be, and the MP3 hint compares a minute with 16-bit WAV at 44.1 kHz. Default: sizes only. stream big: an MP3 or WAV estimated at 200 MB or more is written straight to a file the visitor chooses, as it converts, where the browser has showSaveFilePicker (Chrome and Edge 86 on a computer, Chrome 132 on Android): Convert asks where to save the first such file, one a press, and converts it with the files that need no asking. A WAV written so has no size limit and becomes RF64 past 4 GB. Where the browser has no showSaveFilePicker, a file is built in memory up to TTAudio.limits.wav (2 GB, 300 MB on a phone), and a bigger one is not converted: its file says why. Default: every file is built in memory, up to the engine's limits. wav details: for WAV files the line under the name gives the bit depth ("PCM 24-bit", "32-bit float"), RF64 and BWF (a bext chunk); a note says when the header stated the wrong length and the sound was read to its real end, and a header that cannot be used is named in plain words (no format chunk, no channels or rate, a bit depth such as 12); a WAV that holds MP3 is saved as the MP3 inside, unchanged (cut without re-encoding when trimmed), unless the visitor unticks "Save the MP3 inside as it is" in the editor; the size estimate says when the rate changes; the MP3 hint says MP3 has no bit depth; the file picker also offers .bwf and .rf64 files. Default: WAV files are shown and converted like any other. wav_out options: WAV gets a "Bit depth" choice (16-bit, the default; 24-bit; 32-bit float; 8-bit µ-law and 8-bit A-law, the G.711 of phone systems) and a "Sample rate" choice (as in the file, the default; 44.1, 48, 22.05, 16 or 8 kHz, resampled by the engine's filter), both shown while WAV is chosen; Channels gains "Stereo" (a mono file in both channels, as CD audio always is); the WAV hint describes the bit depth and the size of a minute; the size estimate says when the rate changes, and when this browser decodes the track whole, at 16 bits, so that 24-bit or float holds no more than 16-bit would. Default: a WAV is 16-bit, at the file's own rate. notags switch: a "Save without tags" checkbox under the output options, off at first. Ticked, no tags are written (no LIST INFO or id3 chunk in a WAV, no ID3 tags in an MP3), for samplers and devices that refuse anything but the sound, and the Tags fields are disabled, with a note that says why. Default: no checkbox, and the tags are written. mp3 details: for MP3 files the line under the name says whether the result will be exactly as long as what was encoded (a LAME tag gives the encoder's delay and padding, which are left out) or keeps the encoder's lead-in, about 25 ms at 44.1 kHz (track.mp3.leadIn), for want of one; and the file's message says when an MP3 is cut off: its LAME or VBR header promises more sound than its frames hold. A file this browser can only decode whole (no WebCodecs) and that is longer than TTAudio.limits.whole is refused as soon as it is added, not when it is converted. Default: none of this. sample mp3: "Try a sample sound" adds the sample as an MP3 (192 kbps, made by the MP3 encoder; a WAV where the browser has none). Default: the sample is a WAV. Adding parameters (pair pages). Follow the pattern above: read the value into an acv_ variable below (strip, downcase, a default for unknown values), render the starting state into the HTML so nothing moves when the script runs, put it into CONF in the script, and document it here. Options that change the result go into convertOptions(), which the size estimate and TTAudio.convert both read. The script of presets, tags, saving, stream and wav is in its section "WAV to MP3 options", that of wav_out, notags, mp3 and sample in "MP3 to WAV options". The element ids (m2m-...) are fixed, so a page holds one converter.
