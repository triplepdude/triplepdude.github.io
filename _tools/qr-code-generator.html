Scan the preview with your phone before you download it. **Download PNG** for web pages, documents and slides, and **Download SVG** for print, because a vector file stays sharp at any size. ## What each type puts inside the code A QR code only stores text. Your phone decides what to offer from the way that text is written: | Type | Text inside the code | What the phone offers | |---|---|---| | Link | `https://example.com/` | Open the page | | Email | `mailto:ana@example.com?subject=Hi` | Write an email | | Phone | `tel:+15551234567` | Call the number | | SMS | `SMSTO:+15551234567:Hello` | Send a text message | | Contact | a vCard 3.0 block, `BEGIN:VCARD` … `END:VCARD` | Save the contact | | Location | `geo:48.8584,2.2945` | Open a map | | Event | an iCalendar `BEGIN:VEVENT` … `END:VEVENT` block | Add it to a calendar | Special characters are escaped the way each format requires. Email subjects and bodies are percent-encoded as RFC 6068 describes, so a space becomes `%20` and a line break `%0D%0A`. In contact and event text, a backslash, comma or semicolon gets a backslash in front of it and a line break becomes `\n` (RFC 2426 for vCard, RFC 5545 for iCalendar). The box under the preview shows the exact text, so you can check it. For an event, pick the time zone where it takes place. The start and end are converted to UTC, so a phone in any time zone shows the right local time. **Floating** keeps the clock time as typed, for things like "take your medicine at 8:00" wherever you are. ## Static codes never expire Everything is stored in the code itself. There is no short link or redirect service in between, so the code works for as long as the website or details inside it do, with no account, scan limit or subscription. The other side of that: a printed code cannot be changed. If an address might change, point the code at a page you control and update that page instead. ## Error correction, margin and size QR codes carry recovery data, so a code still scans when part of it is dirty, scratched or covered. | Level | Recovers about | Good for | |---|---|---| | L | 7% | Screens, smallest pattern | | M | 15% | Most uses (default) | | Q | 25% | Prints that get handled | | H | 30% | Codes with a logo | A logo covers part of the pattern, so adding one switches to level H, and the logo is limited to a quarter of the code's width. Keep the plain border around the code, called the quiet zone. The QR standard, ISO/IEC 18004, asks for at least 4 modules (the small squares). Longer content means more, smaller modules. A common rule of thumb is to print a code at least 2 cm (about 0.8 in) wide and roughly one tenth of the distance people will scan it from, so a poster read from 3 m needs a code about 30 cm wide. ## Colours and contrast Scanners look for dark modules on a light background. The contrast figure is the difference in brightness (relative luminance) between your two colours, where black on white is 100%. Aim for 70% or more. Below about 40% many phones struggle, and light modules on a dark background are not read by every scanner app. faq: - q: Do these QR codes expire? a: No. They are static codes, so the link or text is stored in the code itself and nothing sits in between that could be switched off.
