To convert a file, press **Open file**, drop the file on the box or paste a copied image. The result can be copied, downloaded or used as the next input. ## What is Base64? Base64 writes binary data with 64 harmless characters: A to Z, a to z, 0 to 9, `+` and `/`. It exists for channels that carry only text, such as email, JSON, XML and URLs. The rules are in RFC 4648: every 3 bytes (24 bits) are cut into four 6-bit numbers, and each number picks one character. When the last group has only 1 or 2 bytes, `==` or `=` fills it up to four characters. | Text | Bytes (hex) | Base64 | |---|---|---| | `Man` | 4D 61 6E | `TWFu` | | `Ma` | 4D 61 | `TWE=` | | `M` | 4D | `TQ==` | Four characters for every three bytes is why Base64 is **33% larger** than the data. Padding and line breaks add a little more. ## Options - **URL-safe** swaps `+` and `/` for `-` and `_`, which need no escaping in URLs and file names. JSON Web Tokens use this alphabet without padding. To percent-encode text for a link or a query string instead, use the [URL encoder and decoder](/url-encode-decode/). - **No = padding** leaves out the `=` at the end. A decoder can work out the length without it. - **Line length** breaks the output every 76 characters, the limit MIME sets for email (RFC 2045), or every 64, as in the PEM files of certificates and keys (RFC 7468). - **Strict** decoding accepts one alphabet, complete padding and line breaks, and nothing else. Without it the decoder skips white space and stray characters, reads both alphabets, forgives missing padding, undoes URL encoding such as `%3D`, takes the `\n` of a JSON string for a line break and drops the BEGIN and END lines of a PEM block. ## Why does decoded text show strange characters? Base64 stores bytes, not letters. To show text, the bytes must be read with the encoding they were written in. Most text today is UTF-8, but é is the two bytes C3 A9 in UTF-8 and the single byte E9 in Windows-1252, so `6Q==` decodes to � as UTF-8 and to é once **Text encoding** is set to Windows-1252. If � appears, try another encoding. When the data is a file and no text at all, download it; the **hex dump** shows its first bytes. ## Images and data URIs A data URI puts a whole file inside a URL (RFC 2397): `data:image/png;base64,iVBORw0KGgo…`. The part before the comma names the media type and says that Base64 follows. Paste a data URI or bare Base64 and the page recognises PNG, JPEG, GIF, WebP, SVG, PDF, ZIP and other formats by their first bytes, shows images, and offers the file as a download with the right extension. To make a data URI, open an image and tick **As a data URI**; the result works in an `` attribute or a CSS `url()`. It makes data safe to carry through text-only channels and hides nothing, so never use it to protect a password or a secret. - q: How do I decode a Base64 image? a: Paste the Base64 string into the box, with or without its `data:image/...;base64,` prefix. The page shows the picture with its size in pixels, and the Download button saves it as a PNG, JPEG, GIF, WebP or SVG file. - q: Why does btoa() fail on emoji and other Unicode text? a: The browser's `btoa()` only takes characters with code points below 256 and throws an InvalidCharacterError for anything else, such as "✓", "€" or an emoji.
