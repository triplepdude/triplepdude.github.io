Browser Test" description: See which browser, version and operating system you are using, with your user agent, client hints, live feature tests and fingerprint signals. category: Device Tests keywords: [what browser am i using, what is my browser, browser test, browser checker, my user agent, browser feature test, browser fingerprint test, what version of chrome do i have] howto: | ## How this browser test works Everything on this page is worked out by JavaScript on your device. The summary combines your user agent string with User-Agent Client Hints, which Chrome, Edge and other Chromium browsers provide. Where a simple property check could mislead, the feature grid tests for real: it creates WebGL contexts, asks for a WebGPU adapter, decodes tiny AVIF, WebP and JPEG XL images, validates WebAssembly modules and asks the media stack about each codec. **Copy report** gives IT support a plain-text summary, and **Download report** saves everything as JSON. ## Find your browser version by hand | Browser | Where to look | |---|---| | Chrome | Menu (⋮) > Help > About Google Chrome | | Edge | Menu (…) > Help and feedback > About Microsoft Edge | | Firefox | Menu (☰) > Help > About Firefox | | Safari on a Mac | Safari menu > About Safari | | Safari on iPhone or iPad | Settings > General > About (Safari's version matches iOS) | | Chrome on Android | Menu (⋮) > Settings > About Chrome | | Samsung Internet | Menu (☰) > Settings > About Samsung Internet | Chrome, Edge and Firefox check for updates when you open that page; restart the browser when asked. Safari updates with macOS or iOS through Software Update, and phone browsers update from the App Store or Google Play. This page cannot tell you whether a newer version exists, because that would need an online lookup. ## Why the user agent can be wrong The user agent string is no longer a reliable ID. Chrome and Edge send a reduced string: the version always ends in .0.0.0 and Android phones appear as "Android 10; K". In every major browser, Windows 11 appears as "Windows NT 10.0", the same as Windows 10, and a recent Mac as running macOS 10.15. Since iOS 26, Safari reports an older, frozen iOS version (18.6 or 18.7). Brave and Vivaldi send exactly the same string as Chrome, Edge differs only by an "Edg/" token, and extensions or developer tools can replace the string entirely. Client Hints supply the hidden details in a structured form, which is why this page reads them where they exist. ## Feature detection beats browser sniffing Feature detection asks the browser whether it can do something instead of guessing from its name. A site that blocks "unsupported browsers" by user agent can lock out a capable browser, while one that tests `CSS.supports('selector(:has(a))')` or tries to create a WebGL context gets the right answer even for a browser it has never heard of. Some features need more than browser support: SharedArrayBuffer only works on pages that are cross-origin isolated with COOP and COEP headers. GitHub Pages, which hosts this site, cannot send those headers, so SharedArrayBuffer shows as unavailable here even in browsers that support it. ## Fingerprinting and how to reduce it A fingerprint combines many small signals, such as fonts, screen size, time zone, GPU and tiny differences in how your device draws graphics or processes audio, into an identifier that can recognise you without cookies. The hashes on this page show what any site could compute. To be harder to track, use a browser that limits or randomises these signals, such as Brave, Firefox with Enhanced Tracking Protection set to Strict, Safari or Tor Browser. Keep extensions and extra fonts to a minimum, and leave browser zoom and language at common settings. To test individual devices, use the [screen resolution checker](/screen-resolution/), [webcam test](/webcam-test/), [mic test](/mic-test/) and [keyboard tester](/keyboard-tester/). faq: - q: Is any of this information uploaded or stored? a: No. Every check runs in JavaScript on your device. None of the results are sent to a server, logged, or saved in cookies or browser storage, and the fingerprint hashes are gone when you close the tab. The report only exists when you copy or download it, and then only on your clipboard or in your Downloads folder. As with any website, the request that loaded this page carried your user agent string and basic Client Hints, which the web host receives. - q: Does this page tell me whether my browser is up to date? a: No. That would mean looking up the newest release online, and the answer would soon be out of date. Open your browser's About page as shown in the table above. Chrome, Edge and Firefox check for updates there and offer to restart. - q: Why does the page say Chrome when I use a different browser? a: Brave, Vivaldi and several other browsers are built on Chromium and send the same user agent as Chrome. Brave is recognised through its `navigator.brave` property, and Edge, Opera and Samsung Internet through their own user agent tokens or Client Hints, but some browsers cannot be told apart from Chrome at all. - q: Why are WebGL or WebGPU shown as unsupported when my browser supports them? a: These checks create a real graphics context, so they fail when hardware acceleration is off, the graphics driver is blocklisted or the GPU process has crashed. In Chrome or Edge, open `chrome://gpu` or `edge://gpu` to see why. WebGPU also needs a supported GPU and is not yet turned on for every operating system. - q: Why are my fingerprint hashes different in another browser or a private window? a: The hashes depend on the browser and its version, the graphics driver, installed fonts and settings, so another browser on the same computer gives different values. Brave adds small random changes for each site and session, and Safari and Firefox limit or add noise to some signals, especially in private windows. That is the protection working. ---

      Fingerprint signals

      Fingerprinting recognises a browser from details it reveals without asking, such as how it draws graphics, processes audio and which fonts it has, instead of from a cookie. These SHA-256 hashes are what any site could compute. They are made on your device, never sent anywhere and not stored.

      In the same browser they usually stay the same on every visit, and they often differ in other browsers and on other devices, though identical devices with the same software, such as two iPhones of the same model, can give the same values. Brave, Firefox, Safari and Tor Browser randomise or limit some of them. How unique they make you cannot be known without a database of other visitors, which this page does not have.
