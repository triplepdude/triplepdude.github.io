--- title: Unix Timestamp Converter (Epoch Time) description: Convert Unix epoch timestamps to dates and back. Detects seconds, milliseconds, microseconds or nanoseconds and shows UTC, local, ISO 8601 and RFC 2822. category: Date & Time keywords: [unix timestamp converter, epoch converter, unix time, epoch time, timestamp to date, date to timestamp, current unix timestamp, milliseconds to date] howto: | ## How to use it The clock at the top shows the current Unix time, ticking live. A copy button copies the value at the moment you click it. - **Timestamp to date:** paste a number. The unit is detected from its size, and you can override it. You get UTC, local time in any time zone, ISO 8601, RFC 2822, the HTTP date format and a relative time. Thousands separators, negative values, decimals and forms like `1e9` are accepted. - **Date to timestamp:** choose a date, a time and the time zone that time is in. You can also paste a date string such as `2001-09-09T01:46:40Z` or `Sun, 09 Sep 2001 01:46:40 GMT`. A string without an offset is read in the time zone you selected. ## What Unix time is Unix time counts the seconds since 00:00:00 UTC on 1 January 1970, the Unix epoch. It ignores leap seconds, so every day is exactly 86,400 seconds long. The number is the same everywhere on Earth at a given instant; time zones only matter when you turn it into a clock time. ## How the unit is detected | Digits today | Read as | Typical source | |---|---|---| | 10 | seconds | `date +%s`, PHP `time()`, Python `time.time()` | | 13 | milliseconds | JavaScript `Date.now()`, Java `currentTimeMillis()` | | 16 | microseconds | many databases and tracing tools | | 19 | nanoseconds | Go `UnixNano()`, Python `time.time_ns()` | Precisely, values below 1011 are read as seconds, below 1014 as milliseconds, below 1017 as microseconds, and anything larger as nanoseconds. With these limits, any moment from March 1973 to the year 5138 is detected correctly in every unit. For a millisecond value before 1973, choose the unit by hand. Values are handled as exact integers, so a 19-digit nanosecond timestamp keeps all its digits instead of being rounded. ## Negative timestamps Moments before 1970 are negative: `-1` is 1969-12-31T23:59:59Z, and the Apollo 11 Moon landing, 1969-07-20T20:17:40Z, is `-14182940`. Negative values are valid Unix time, but some older software and file formats reject them, so test before relying on them. ## The year 2038 problem Many older systems store Unix time in a signed 32-bit integer, whose largest value is 2,147,483,647, or 2038-01-19T03:14:07Z. One second later the counter wraps to -2,147,483,648, which reads as 1901-12-13T20:45:52Z. Current 64-bit operating systems use a 64-bit `time_t` and are not affected, but embedded devices, old binary file formats and 32-bit database columns still are. For example, MySQL's `TIMESTAMP` type ends at 2038-01-19 03:14:07 UTC. The converter flags any value outside the 32-bit range. ## Formats in the results - **ISO 8601** (and RFC 3339): `2001-09-09T01:46:40Z`, or with an offset such as `+02:00`. Fractional seconds are shown only when present. - **RFC 2822**, used in email headers: `Sun, 09 Sep 2001 01:46:40 +0000`. - **HTTP date** (RFC 9110), used in `Date`, `Expires` and `Last-Modified` headers: always in GMT, `Sun, 09 Sep 2001 01:46:40 GMT`. faq: - q: What is the current Unix timestamp? a: It is the ticking number at the top of this page, taken from your device's clock. Unix time is the same in every time zone, so the value is identical for everyone at the same instant. - q: How can I tell seconds from milliseconds? a: Count the digits. A current timestamp in seconds has 10 digits and one in milliseconds has 13. The converter checks the size for you and shows which unit it used. - q: Does Unix time count leap seconds? a: No. Unix time treats every day as exactly 86,400 seconds. During a leap second, systems repeat or smear a second, so a leap second itself has no Unix timestamp of its own. - q: Why is my converted time off by a few hours? a: The timestamp itself is always UTC-based. An offset of whole hours usually means the date was read or written in the wrong time zone. Check the UTC row and the time zone selector. - q: Is anything I enter uploaded? a: No. All conversions happen in your browser with JavaScript. Nothing you type is sent to a server or stored. ---
