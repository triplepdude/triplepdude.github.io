Every view stays in sync, and the ready-to-paste commands update as you go. Enter your own file name to put it in the commands, and tick **Directory** to see what each permission means for a folder. ## How the octal number works Each permission has a value: read is 4, write is 2 and execute is 1. Add them up for each class of user and write the three sums in the order owner, group, others. `rwx` is 4+2+1 = 7 and `r-x` is 4+1 = 5, so `rwxr-xr-x` is 755. An optional fourth digit in front holds the special bits: setuid is 4, setgid is 2 and sticky is 1, so `4755` is 755 plus setuid. | Digit | Permissions | Digit | Permissions | |---|---|---|---| | 0 | `---` none | 4 | `r--` read | | 1 | `--x` execute | 5 | `r-x` read, execute | | 2 | `-w-` write | 6 | `rw-` read, write | | 3 | `-wx` write, execute | 7 | `rwx` all | ## Files and directories On a file, read lets you see the contents, write lets you change them and execute lets you run the file as a program. On a directory, read lets you list the names in it, write lets you create, rename and delete entries, and execute lets you enter it and reach files inside by name. Write on a directory does nothing without execute, and a directory without execute cannot be used even if it is readable. Only one class applies to you: if you own the file, the owner bits decide, even when the group or others bits allow more. So `chmod 077` locks the owner out while everyone else has full access. ## Special bits and the s, S, t, T letters - **setuid** (4000) makes a program run with its owner's rights. `/usr/bin/passwd` is `rwsr-xr-x` so it can update the password file. Linux ignores setuid on scripts that start with `#!`. - **setgid** (2000) on a program runs it with the file's group. On a directory, new files inherit the directory's group, which is handy for shared project folders. - **sticky** (1000) on a directory means only a file's owner, the directory's owner or root can delete or rename entries in it. `/tmp` is `rwxrwxrwt` (1777) for this reason. `ls -l` shows these bits in the execute position: a lowercase `s` or `t` means the bit and execute are both set, and an uppercase `S` or `T` means the bit is set without execute. For setuid, `S` means it has no effect. ## Tips - Setting 755 or 644 on a whole tree with `chmod -R` gives every file the same mode. To give directories 755 and files 644, run `find DIR -type d -exec chmod 755 {} +` and `find DIR -type f -exec chmod 644 {} +`, or use `chmod -R u=rwX,go=rX DIR`, where the capital `X` adds execute only to directories and files that already have it. - The symbolic command adds the sticky bit as a separate `+t`, because some chmod versions, including the BSD one on macOS, ignore `t` attached to `o`. - On a directory, GNU chmod keeps an existing setuid or setgid bit when you give a three- or four-digit number, or a symbolic `=` that does not mention it. Use five digits, as in `00755`, or `g-s` to clear it. faq: - q: What does chmod 755 mean? a: The owner can read, write and execute (7), and the group and everyone else can read and execute (5). It is the usual mode for programs, scripts and directories that others need to use but not change. - q: What is the difference between chmod 644 and 755? a: 644 (`rw-r--r--`) has no execute permission, which suits regular files such as web pages, images and config files. 755 adds execute for everyone, which programs need to run and directories need to be entered. - q: Why should I avoid chmod 777? a: 777 lets every user on the system change or replace the file, and for a directory, delete anything in it. Fix the owner or group with `chown` or `chgrp` and use 755, 775 or 770 instead. - q: What do the capital S and T in ls -l mean? a: They mean setuid, setgid or the sticky bit is set but the matching execute bit is not. A lowercase `s` or `t` means both are set. - q: Is anything I enter sent to a server? a: No. The calculator runs entirely in your browser. Nothing you type is uploaded or stored. ---
