--- title: "Hash Generator: MD5, SHA-1, SHA-256, SHA-512" description: Generate MD5, SHA-1, SHA-256, SHA-384 and SHA-512 hashes of text or files in hex or Base64, and check a download against its expected checksum. category: Security & Network keywords: [hash generator, md5 hash generator, sha256 hash generator, sha512 generator, sha1 hash, file checksum, checksum calculator, verify file hash] howto: | ## How to use the hash generator Type or paste text, or switch to **File** and choose or drop a file. All five hashes appear at once, in hexadecimal and in Base64. Tick **Uppercase hex** if the checksum you compare against is written in capitals. To check a download, paste the checksum published next to it into **Compare with expected hash**. The page tells you which algorithm matches, or that none does. Besides a bare hash it accepts a line copied from `sha256sum` output (`hash filename`), the BSD format `SHA256 (file) = hash`, OpenSSL's `SHA2-256(file)= hash`, the output of PowerShell's `Get-FileHash` or Windows `certutil -hashfile`, and Subresource Integrity values such as `sha384-oqVu…`. Text is hashed as UTF-8, the encoding of most text files and web pages, so the result matches `sha256sum` run on a UTF-8 file with the same content. Set **Input is** to *Hex bytes* or *Base64* to hash raw bytes instead, for example a key or a value copied from a packet dump. ## How it works The SHA hashes come from the Web Crypto API (`crypto.subtle.digest`), the browser's native cryptography code. Web Crypto does not offer MD5, so this page computes MD5 with its own JavaScript implementation of RFC 1321. Files are read with the File API in 4 MB pieces: MD5 is updated piece by piece, a progress bar tracks big files, and the page stays responsive. Nothing is uploaded. MD5 is specified in RFC 1321; SHA-1 and the SHA-2 family (SHA-256, SHA-384, SHA-512) in NIST's FIPS 180-4. | Algorithm | Digest size | Collisions | |---|---|---| | MD5 | 128 bits, 32 hex characters | Broken | | SHA-1 | 160 bits, 40 hex characters | Broken | | SHA-256 | 256 bits, 64 hex characters | No practical attack | | SHA-384 | 384 bits, 96 hex characters | No practical attack | | SHA-512 | 512 bits, 128 hex characters | No practical attack | Hex and Base64 are the same bytes written two ways: the 16 bytes of an MD5 digest become 32 hex characters or 24 Base64 characters ending in `==`. ## Which hash to use To detect a download that was cut short or corrupted, any of them works: use the one the publisher lists. When someone might swap the file on purpose, rely on SHA-256 or longer. MD5 collisions (two different files with the same hash) take seconds on an ordinary computer, and a practical SHA-1 collision was published in 2017. A checksum only protects you if it comes from a source the attacker can't change: someone who can replace the file on a mirror may be able to replace a checksum stored next to it as well. None of these is suitable on its own for storing passwords. They are designed to be fast, which helps anyone guessing passwords. Use a deliberately slow password hash such as Argon2id, scrypt or bcrypt. ## Why a hash might not match - **Trailing newline.** `echo "abc" | sha256sum` hashes `abc` plus a line feed. Use `printf '%s' "abc"` or `echo -n` to get the value shown here. - **Line endings.** A browser text box turns every line break into a single line feed (LF). If the original text used Windows CRLF line breaks, hash the file itself rather than pasting its contents. - **Encoding.** The same characters stored as UTF-16 or Latin-1 are different bytes, and so give a different hash. - **Invisible characters.** A copied string can carry a leading space, a non-breaking space or a zero-width character. The byte count under the text box helps you spot them. faq: - q: Is my text or file uploaded anywhere? a: No. The hashes are calculated in your browser with JavaScript and the Web Crypto API. Your text and files never leave your device, and nothing is stored. - q: Why is my hash different from the one my terminal prints? a: Usually because `echo` adds a newline. `echo "hello" | md5sum` hashes six bytes, not five. Run `printf '%s' "hello" | md5sum` instead, or hash the file itself here. - q: Can a hash be decrypted back to the original text? a: No. A hash is a one-way fingerprint, not encryption. Short or common inputs can still be found by guessing and comparing, which is why unsalted fast hashes should never protect passwords. - q: How large a file can I hash? a: Hundreds of megabytes work on a typical computer. Web Crypto needs the whole file in memory for the SHA hashes, so a file of several gigabytes can exceed what the browser allows; the page shows a message if that happens. - q: Is MD5 still safe to use? a: For spotting accidental corruption, yes. For anything security-related, no. Anyone can create two different files with the same MD5 hash, so use SHA-256 when tampering is a concern. ---
