--- title: UUID Generator (v4 & v7) and Decoder description: Generate random v4 or time-ordered v7 UUIDs in bulk, uppercase, without hyphens or in braces, and decode any UUID's version, variant and timestamp. category: Developer keywords: [uuid generator, uuid v4 generator, uuid v7 generator, guid generator, bulk uuid generator, uuid decoder, uuid validator, uuid timestamp] howto: | ## How to use it Pick a version, choose how many UUIDs you need (up to 1,000) and press **Generate**. Tick the boxes for uppercase, no hyphens or curly braces; changing the format re-formats the same list rather than making new IDs. **Copy** puts the whole list on your clipboard and **Download .txt** saves it with one UUID per line. To look inside an existing UUID, paste it into **Decode a UUID**. It accepts the usual forms: with or without hyphens, in braces, upper or lower case, or as a `urn:uuid:` name. You get the version, the variant, the 128-bit value as an integer, and for time-based versions the moment it was made. ## v4 or v7? A **v4** UUID is 122 random bits plus the version and variant markers. This page makes them with the browser's `crypto.randomUUID()`, which uses the same cryptographically secure generator as `crypto.getRandomValues()`. A **v7** UUID starts with a 48-bit count of milliseconds since 1970-01-01 UTC, followed by 74 random bits, so v7 IDs sort by creation time. As database primary keys they keep B-tree indexes append-mostly, which usually means faster inserts and less index bloat than random v4 keys. The trade-off is that anyone holding the ID can read when it was created. | Bits | v7 field | Contents | |---|---|---| | 0–47 | `unix_ts_ms` | milliseconds since the Unix epoch | | 48–51 | `ver` | always `0111` (7) | | 52–63 | `rand_a` | random | | 64–65 | `var` | always `10` | | 66–127 | `rand_b` | random | In text form the version is the first digit of the third group and the variant shows in the first digit of the fourth group, which is 8, 9, a or b for standard UUIDs: `xxxxxxxx-xxxx-7xxx-9xxx-xxxxxxxxxxxx`. ## Keeping v7 in order Many v7 IDs can share one millisecond. Following RFC 9562 section 6.2 (method 2, "monotonic random"), the generator treats the 74 random bits as a counter: the first ID in a millisecond gets fresh random bits, and each later one adds a random amount of up to 232. A batch of 1,000 therefore sorts in exactly the order it was made, and each step still adds 32 bits of randomness. If the computer's clock steps backwards, the last timestamp is reused so the order still holds. ## Versions at a glance | Version | Built from | Timestamp | |---|---|---| | 1 | time and node (often a MAC address) | 100 ns steps since 1582-10-15 | | 2 | like v1, with a POSIX user or group ID | coarse, low bits replaced | | 3, 5 | MD5 or SHA-1 hash of a namespace and a name | none | | 4 | random bits | none | | 6 | v1's fields reordered to sort by time | as v1 | | 7 | Unix milliseconds and random bits | milliseconds since 1970 | | 8 | a vendor-defined layout | depends | The **nil UUID** is all zeros and the **max UUID** is all `f`. Both are valid special values: nil usually stands for "no ID", and RFC 9562 suggests max as a sentinel, for example to mark the end of a list. A **GUID** is Microsoft's name for the same 128-bit identifier. The registry style wraps it in braces and uses capitals, as in `{0F8FAD5B-D9CB-469F-A165-70867728950E}`. When you handle raw bytes, note that Windows and .NET store the first three groups little-endian, so the byte order differs from the text even though the text form is identical. faq: - q: Can two generated UUIDs ever be the same? a: In theory yes, in practice no. A v4 UUID has 122 random bits, so you would need to make about 2.7 quintillion (2.7 × 1018) of them for a 50% chance of a single repeat. A v7 UUID has 74 random bits, but only IDs made in the same millisecond can clash, and within one batch from this page each ID is larger than the one before, so none can repeat. - q: Is a GUID the same as a UUID? a: Yes. GUID is Microsoft's term for a UUID. The text format is the same; Windows tools often show it in capitals and curly braces, which the checkboxes above reproduce. - q: Can I find out when a UUID was created? a: Only for versions that store a time, which are 1, 6 and 7 (and 2, roughly). Paste one into the decoder to see the date. Version 4 is pure randomness, and versions 3 and 5 are hashes, so they contain no date. - q: Should I use v4 or v7 for database keys? a: v7 is usually the better choice for primary keys because new rows land at the end of the index. Use v4 when the ID must not reveal when the record was created. - q: Are these UUIDs generated on a server? a: No. They are created in your browser with the Web Crypto API, and the decoder also runs locally. Nothing is uploaded, logged or stored. ---
