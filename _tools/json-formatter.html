Everything runs in your browser. category: Developer keywords: [json formatter, json validator, json beautifier, json viewer, json minify, json pretty print, json lint, fix json, json escape unescape] howto: | ## How to format JSON Paste JSON into the box, or open or drop a file. The result follows as you type. **Format** puts every value on its own line, indented by 2 spaces, 4 spaces or a tab. **Minify** removes every space and line break outside strings. **Tree view** shows objects and arrays that open and close. **Sort keys** orders the keys of each object by Unicode code point, so capitals come before lower case; arrays keep their order. Only the white space changes. Strings and numbers are copied exactly as written, so `1.0` stays `1.0` and `12345678901234567890` keeps every digit. Keys keep their order, and a key that appears twice is kept twice, with a warning. ## Why is my JSON invalid? The checker follows RFC 8259 and ECMA-404, the two standards that define JSON, and gives the line, column and reason for the first problem. These are the usual ones: | Problem | Not JSON | JSON | |---|---|---| | Trailing comma | `[1, 2,]` | `[1, 2]` | | Single quotes | `{'a': 'b'}` | `{"a": "b"}` | | Unquoted key | `{a: 1}` | `{"a": 1}` | | Comment | `{"a": 1} // note` | `{"a": 1}` | | Python or JavaScript word | `True`, `None`, `NaN` | `true`, `null`, `null` | | Line break inside a string | a real line break | `\n` | | Number format | `.5`, `+1`, `0x1F` | `0.5`, `1`, `31` | **Fix** repairs all of these in one step. It also straightens curly quotes from a word processor, adds missing commas, closes brackets left open at the end, and wraps several values in a row (JSON Lines) in one array. It lists what it changed, and Undo brings your text back. What it cannot know is left to you: `007` may be a number or a code that needs quotes. ## JSON and JavaScript objects JSON was derived from JavaScript's object syntax, but it is stricter, and it is text, not an object in memory. Keys and strings need double quotes. There are no comments, no trailing commas, no `undefined`, no functions and no dates, and numbers are plain decimals. `JSON.stringify` turns a JavaScript value into JSON text and `JSON.parse` reads it back. Reading JSON into JavaScript can change it. Whole numbers beyond 9,007,199,254,740,991 (2^53 − 1) can be rounded, as can any number with more than 15 significant digits; `1e-400` becomes `0`, `1.0` becomes `1`, keys that look like whole numbers move to the front, and of two equal keys only the last survives. This page reads the text itself, so none of that happens here, and it tells you when a number or a repeated key is at risk. ## Escape and unescape **Escape** turns any text into one JSON string: `"` becomes `\"`, a backslash becomes `\\` and a line break becomes `\n`. Use it to put JSON inside JSON, such as a request body in a config file. **Unescape** does the reverse. That is how to read "stringified" JSON such as `"{\"id\": 1}"` from a log: unescape it, then choose **Use as input** to format it. ## Large files Text longer than 100,000 characters is read in a background thread, so the page stays responsive. Files up to 50 MB can be opened. A file or paste that makes the text longer than a million characters is kept out of the text box, only the start of a very long result is shown, and Copy and Download give all of it. The tree builds only the rows you open, 100 at a time, which makes it the practical way to look through a large file. To compare two JSON documents, format both with sorted keys and paste them into [Text compare](/text-compare/). The payload of a JSON Web Token can be read with the [JWT decoder](/jwt-decoder/), and JSON carried in a query string with the [URL encoder and decoder](/url-encode-decode/). faq: - q: Is my JSON uploaded or stored anywhere? a: No. The page reads, checks and formats your JSON with JavaScript in your own browser, and opening a file reads it from your device only. Nothing is sent to a server, and nothing is kept in cookies or browser storage. - q: Can JSON have comments? a: 'No. JSON has no comment syntax, so a strict parser stops at `//` or `/* */`. Some tools read a looser dialect: VS Code uses "JSON with Comments" for settings.json, and JSON5 allows comments too. Remove the comments before the text goes to a JSON parser; Fix does that here.' - q: What does "Unexpected token < in JSON" mean? a: 'The text handed to the parser is not JSON at all. It starts with `<`, so it is almost always an HTML page, such as an error or login page, that a server returned where JSON was expected.
