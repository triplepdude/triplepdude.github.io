--- title: URL Encoder and Decoder (Percent-Encoding) description: Encode or decode URLs and query strings with percent-encoding, see each character that changed, and choose how plus signs are read. Runs in your browser. category: Developer keywords: [url encoder, url decoder, url encode decode, percent encoding, encodeuricomponent, url decode online, urlencode, query string decoder] howto: | ## How to encode or decode a URL Type or paste text into the box and choose **Encode** or **Decode**. The result follows as you type, with every part that changed marked, and the table under it lists each character next to its code. Copy the result, download it, or press **Swap** to send it back the other way. Percent-encoding writes a character as `%` and the two hexadecimal digits of each of its bytes in UTF-8. A space is byte 20 in hexadecimal, so it becomes `%20`. The pound sign £ takes two bytes and becomes `%C2%A3`, an emoji such as 😀 takes four, and the percent sign itself becomes `%25`. ## Which mode to use | Mode | Leaves as they are | Use it for | |---|---|---| | Component | A–Z a–z 0–9 `- _ . ! ~ * ' ( )` | one query value or path segment, like `encodeURIComponent` | | Whole URL | the same and `; / ? : @ & = + $ , #` | a complete address, like `encodeURI` | | Form data | A–Z a–z 0–9 `* - . _`, space as `+` | form posts and query strings, like `URLSearchParams` and Java's `URLEncoder` | | RFC 3986 | A–Z a–z 0–9 `- . _ ~` | strict encoders such as PHP's `rawurlencode` and Python's `quote(s, safe='')` | Encode a value before you put it into a URL. In `?q=fish & chips` the `&` would end the value, so the value has to become `fish%20%26%20chips`. **Whole URL** leaves `&`, `=`, `?` and `/` alone, because in a full address they are structure. For the same reason it cannot protect a value that contains them. ## Why a space is sometimes + and sometimes %20 HTML forms have written a space as `+` since HTML 2.0 in 1995, and browsers still send form data that way, in the query string or the body of the request; the format is called `application/x-www-form-urlencoded`. Everywhere else in a URL only `%20` means a space, and a `+` in a path is a plus sign. So Decode reads `+` as a space in the query string, after the `?`, and in a line that does not start with a scheme such as `https:` or with a `/`, which it takes for form data. Elsewhere it keeps the `+`. The **Plus signs** setting overrides this. A real plus sign in form data is written `%2B`. ## Reserved and unreserved characters RFC 3986, the Internet standard for URL syntax, calls A–Z a–z 0–9 `- . _ ~` *unreserved*: they never need encoding. The *reserved* characters `: / ? # [ ] @ ! $ & ' ( ) * + , ; =` separate the parts of a URL, and must be encoded when they are data and not separators. Everything else is always encoded: spaces, double quotes, `< > \ ^ { | }` and every character outside ASCII. The table in the tool shows each character in each mode. ## When decoding goes wrong - **Still full of %25?** The text was encoded twice: `%2520` is an encoded `%20`. Decode it again; the page offers to. - **A � in the result** means the bytes are not valid UTF-8. Older sites used other character sets, in which `%E9` alone is é. Try Windows-1252 or another set from the list. - **A % without two hexadecimal digits after it** is left as it is and reported with its line and column. To read JSON or a token carried in a query string, decode it here and pass it to the [JSON formatter](/json-formatter/) or the [JWT decoder](/jwt-decoder/). To turn a link into a code for print, use the [QR code generator](/qr-code-generator/). faq: - q: Is the text I encode or decode sent anywhere? a: No. Encoding and decoding are done by JavaScript in your browser, and the page makes no request with your text. Nothing is saved, and the text is not put into the address of this page, so a URL with a token or password in it stays on your device. - q: What do %20, %2F, %3A and %3F mean? a: '%20 is a space, %2F a slash (/), %3A a colon (:) and %3F a question mark (?). Others you will meet are %3D for an equals sign, %26 for an ampersand, %23 for a hash and %25 for the percent sign itself. Each one is the ASCII code of the character in hexadecimal.' - q: What is the difference between encodeURI and encodeURIComponent? a: 'encodeURIComponent encodes everything except A–Z a–z 0–9 and `- _ . ! ~ * '' ( )`, so a `/`, `?`, `&`, `=` or `#` inside a value becomes `%2F`, `%3F`, `%26`, `%3D` or `%23` and cannot break the URL. Use it for each query value or path segment. encodeURI also leaves `; , / ? : @ & = + $ #` alone, so that a complete address keeps its structure, which means it cannot protect a value that contains them. Neither writes a space as `+`; URLSearchParams does, for form data.' - q: Does URL encoding hide or encrypt data? a: No. Percent-encoding is only another way of writing characters, and anyone can turn it back without a key, as this page does. It makes text safe to carry in a URL, not secret. A password or token in a URL is still readable in browser history and server logs. - q: Why does decodeURIComponent throw "URI malformed"? a: 'JavaScript throws a URIError when a % is not followed by two hexadecimal digits, or when the decoded bytes are not valid UTF-8, such as %E9 from a system that used Latin-1. Chrome and Node.js word it as "URI malformed". This page decodes what it can and tells you where the problem is; in your own code, catch the error or fix the encoding where the URL is made.' ---
